## Password Rules

- Related commit: **Commit 4 - Added password generator class**
- Password is randomly generated by the application.
- Password length is between 4 and 5 characters.
- This follows the assignment rule `[4–6)`.
- `[4–6)` means 4 is included and 6 is not included.
- The password uses a small character set for testing.
- The small character set helps the demo finish quickly during viva.

## Hashing

- Related commit: **Commit 5 - Added SHA256 hash service**
- The application uses SHA256 hashing.
- A constant static salt is added to the password.
- The password and salt are combined before hashing.
- The hash is shown in the GUI.
- The original password is not compared directly during brute force.
- Each guessed password is hashed and compared with the target hash.

## Password Validation

- Related commit: **Commit 7 - Added password validator class**
- PasswordValidator checks whether a guessed password is correct.
- It hashes the guessed password.
- It compares the guessed hash with the target hash.
- This keeps validation separate from generation.

## Brute Force Generator

- Related commit: **Commit 8 - Added brute force generator class**
- BruteForceGenerator creates possible password combinations.
- It only generates guesses.
- It does not check whether a password is correct.
- This keeps generation independent from validation.

## Brute Force Logic

- Related commits:
  - **Commit 8 - Added brute force generator class**
  - **Commit 9 - Added single-thread brute force attack**
  - **Commit 10 - Added multi-thread brute force attack**
- The brute-force attack starts from password length 1.
- It continues up to maximum length 6.
- The brute-force algorithm does not know the real password length in advance.
- All possible combinations are generated and checked.
- When the correct password is found, the attack stops.

## Single-Thread Attack

- Related commit: **Commit 9 - Added single-thread brute force attack**
- The single-thread attack checks one password guess at a time.
- It uses one execution path.
- It records the number of attempts.
- It records elapsed time.
- It displays the found password in the GUI.

## Multi-Thread Attack

- Related commit: **Commit 10 - Added multi-thread brute force attack**
- The multi-thread attack checks multiple guesses in parallel.
- It uses CPU cores minus one.
- This follows the assignment requirement.
- One CPU core is left free for the operating system and GUI.
- After the password is found, the search stops.

## Performance Comparison

- Related commit: **Commit 11 - Added performance comparison log**
- PerformanceLogger compares single-thread and multi-thread results.
- It shows single-thread elapsed time.
- It shows multi-thread elapsed time.
- It shows the time difference.
- It shows single-thread attempts.
- It shows multi-thread attempts.

## Stop Button

- Related commit: **Commit 12 - Added stop button cancellation logic**
- The stop button uses cancellation logic.
- `CancellationTokenSource` is used to request stopping.
- The attack checks the cancellation request.
- This allows the attack to stop safely.
